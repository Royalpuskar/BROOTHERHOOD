## Judge demonstration and acceptance

- Open the homepage on mobile and desktop; check keyboard navigation, reduced motion, readable text, and optional rendering fallback.
- Complete a fictional cybersecurity challenge and change the kNN example; verify real calculations and corrective feedback.
- Run a local JavaScript learning example; clearly distinguish Study Mode and external compiler tracks.
- Reload to check local progress, and test without optional external services. The public demo has no deployed production backend.
- Review README background, purpose, features, stack and usage; review AI assistance and third-party notices and any external compiler data sharing.
- Verify the registered team roster with the organizer. Invite the confirmed teammate via Settings → Collaborators; the teammate must accept and review changes as CONTRIBUTING.md requires. Never publish student IDs or private contact details.
- Record actual tested URLs, browser/device, commit SHA, results and any failures in team notes. Do not mark browser testing done based on CI alone.

Baseline: GitHub quality run 44245505410 at 494c3bc passed 44 JavaScript tests and one backend test; Pages run 44245505666 passed. New changes need fresh checks. This is not a claim of judging readiness.

## Suggested 90-second pitch (adapt and rehearse)

Students often learn Informatics through static examples. BROOTHERHOOD lets them explore cybersecurity decisions, machine learning and coding through interactive environments. Demonstrate one actual learning challenge and the feedback; then show another model with changed inputs. Finish by explaining accessibility, local data storage, optional external dependencies and why this supports SDG 4. Only present working behavior. Each team member should explain their real contribution.
